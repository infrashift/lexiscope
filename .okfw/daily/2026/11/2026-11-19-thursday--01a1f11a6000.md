# 2026-11-19 Thursday

## Changed
- Phase 6 and ISSUE-006: comment tests for Zig, C and Rust, and for C++ code in a `.h` file. ISSUE-006 is closed.
- `parser.Comments` removes the line break at the end of a line comment. A Rust doc comment no longer fails an assertion.
- [ADR-0010](/decisions/adr-0010-a-ztree-error-fails-the-scan--01a1f4789ef0.md): a ztree error fails the scan with status 2. The message has one `ztree:` prefix.
- Opened [ISSUE-007](/issues/issue-007-c-comments--01a1f4750b43.md) for C++ files.
- Phase 7: lexis reads the comments of `.cc`, `.cpp`, `.cxx`, `.hh`, `.hpp` and `.hxx` files with the C++ grammar of ztree. ISSUE-007 is closed.
- `parser.Comments` reads each line of a line comment separately. A `//` comment that a backslash continues no longer fails an assertion.
- Phase 8 ([ISSUE-008](/issues/issue-008-semscope-in-the-lint-task--01a1f5142ec2.md)): `.semscope.cue` and semscope in the lint task. [ADR-0011](/decisions/adr-0011-semscope-checks-the-power-of-10-rules-in-the-lint-task--01a1f5140d5e.md) records the decision.
- Review against the latest ztree. `go.mod` replaces the binding with `../ztree/bindings/go`, so lexis links the local checkout. ztree `main` is at `70fe5e7` (Phase 18). `zmake ztree` built `libztree.a` with the SHA-256 `2cc1ddd1…`, and `libhash.go` holds the same value. `zmake check` passes with no change to the code. semscope gives 0 findings.
- ISSUE-006 now records the fix of ztree Phase 17. It no longer tells you to run `go clean -cache`.
- `bin/lexis` is now in `~/.local/bin/lexis`.
- The new `install` target in the `ZMakefile` and the `Makefile` runs `build` and copies `bin/lexis` into `$(PREFIX)/bin`. `PREFIX` is `~/.local` by default, as in semscope. The docs site and CLAUDE.md list the target.
- lexis scanned the documentation of ztree and semscope with the `ste-100` ruleset and no vocabulary. Each scan gave warnings only, from the extended rules: ztree 122 in 43 files, semscope 157 in 52 files. Most come from STE-100-06 and STE-100-07, for example `decision`, `divergence`, `conformance` and the `Tracking:` label. A check of a sample found no wrong position and no false finding.

## Learned
- ztree ends the span of a Rust doc comment after the line break. A plain `//` comment ends before it.
- The Go build cache does not see a new `libztree.a`. `go test -c` gave the same binary after a debug build of the library. ztree ISSUE-018 records it. Run `go clean -cache` after a new `libztree.a`.
- ztree Phase 17 fixes the stale library: `zig build lib` writes the hash of `libztree.a` into the binding. `go clean -cache` is not necessary now.
- A raw string `R"(// ...)"` gives no comment span.
- A backslash at the end of a C or C++ `//` comment continues the comment, so the span holds more lines. The V8 diagrams use it. The scan of V8 found it; the unit tests did not.
- The installed semscope was from 2026-11-18, before semscope used ztree. Install semscope again with `zmake install` in semscope after a semscope change.
