# ADR-0013: lexiscope checks the text in the XML doc tags of C#

**Status:** Accepted
**Date:** 2026-11-21
**Source:** [ISSUE-010](/issues/issue-010-c-sharp-comments--01a1fec6a21f.md). User decision on 2026-11-21: remove the XML doc tags, so that lexiscope checks the text in them.

## Context
A C# doc comment is a series of `///` lines with XML doc tags, for example `<summary>`, `<param name="x">` and `<returns>`. Many lines start with a tag and hold prose after it, for example `/// <summary>The class holds the state.</summary>`. The oracle `scripts/ste-check.py` skips each line that starts with `<`, because such a line is HTML or JSX in Markdown. lexiscope applies the same rule to the comments, so it skips most of the prose of a C# doc comment.

A `<code>` block in a doc comment holds code without an indent. lexiscope then reads the code as prose.

## Decision
- For C# only, `appendLineComment` removes the known XML doc tags at the start of a `///` line. A regular expression matches one or more open or close tags with a known name. The known names are the recommended tags of the C# language reference, for example `summary`, `param`, `returns`, `see` and `list`. `docTagRE` in `internal/parser/comments.go` holds the full list of 22 names.
- The cleanup of the oracle already changes each tag in a line to a space, so a tag after the prose needs no change.
- The lines from `<code>` to `</code>` do not count, these two lines too. Each `///` line is a separate comment node, so `docCode` keeps the state from comment to comment.
- A line that starts with another tag, for example `// <auto-generated>`, stays skipped.

## Consequences
- lexiscope checks the prose of the summaries, the parameters and the return values of C# code.
- The Markdown files and the comments of the other grammars do not change, so the parity of STE-100-01 to STE-100-04 with the oracle stays.
- A `<code>` tag without a `</code>` tag skips all the next `///` lines of the file.
- A new XML doc tag needs a new name in the regular expression.

## Alternatives considered
- **Keep the skip of each line that starts with `<`.** Rejected by the user: lexiscope then misses most of the prose of a C# doc comment.
- **Remove each tag at the start of a line.** Rejected: a line such as `// <auto-generated>` is not prose.
- **An XML parser for the doc comments.** Rejected: one regular expression with a bounded set of names is enough, and a parser adds code and a dependency.
