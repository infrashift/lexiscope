# ISSUE-010: C# comments

**Status:** closed · **Phase:** 10

## Description
ztree reads C# files (`ztree.LangCSharp`, ztree ADR-0019), but lexiscope does not. `parser.LangOf` maps no `.cs` extension, so a scan skips each C# file.

A C# doc comment holds XML doc tags, for example `/// <summary>The class holds the state.</summary>`. `appendProse` skips each line that starts with `<`, so the prose in such a line does not count.

## Acceptance Criteria
- [x] `parser.LangOf` maps `.cs` to `ztree.LangCSharp`.
- [x] A `///` line of a C# file loses the XML doc tags at its start, and the text after them counts ([ADR-0013](/decisions/adr-0013-lexiscope-checks-the-text-in-the-xml-doc-tags-of-c-sharp--01a1fec6a230.md)).
- [x] The lines of a `<code>` block do not count. A comment marker in a verbatim string or a raw string is not a comment.
- [x] A comment line that starts with another tag, such as `<auto-generated>`, does not count, as before.
- [x] The help, the error text, the docs pages, the architecture overview and ADR-0002 name C#.
- [x] `zmake check` and `make check` pass.

## Resolution
- `parser.LangOf` maps `.cs` to `ztree.LangCSharp`. The C# comment kind of ztree is `comment`. It covers `//`, `///` and `/* */`, and the span holds no line break.
- For C# only, `appendLineComment` removes the XML doc tags at the start of a `///` line with one regular expression. The known tags are the recommended tags of the C# language reference, for example `summary`, `param`, `returns`, `see` and `list`. The offsets stay correct, because the code cuts the tags from the line and does not change the bytes.
- Each `///` line is a separate comment, so `docCode` keeps the state of a `<code>` block from line to line.
- `TestCSharpComments` reads a summary, a parameter and an example with a code block. It also reads a verbatim string, a raw string, a block comment, a trailing comment and a line with inline tags.
- The Markdown files and the other grammars do not change, so the parity with `scripts/ste-check.py` stays.
